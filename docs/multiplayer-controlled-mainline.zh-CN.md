# 受控主线 v1：服务器战斗、捕获与培养

本文保留历史 v1 规则说明。新角色入口已经切换为[原版主线](multiplayer-original-rules-completion.zh-CN.md)；生产环境关闭 v1 新奖励，只有已有对局与已提交回执可继续恢复。服务端旧资产可按明确规则迁移，本地历史资产不导入。下文的 14 章与简化规则不代表当前原版角色规则。

分支：`codex/admin-operations`；交付日期：2026-10-23。沿用「新建受控在线角色，旧资产不导入」的已确认选择。

## 内容与入口

在线暂停菜单 → 受控在线角色 → 选择角色 → 受控主线与培养。角色首次进入可选择妙蛙种子、小火龙或杰尼龟，服务器生成唯一 `cm_...` 编号。所有对象仅存在于服务端受控角色中，客户端不把它们写入旧训练师、背包或主线存档。

当前规则是独立的 `controlled-adventure-v1` 章节模式，使用已安装游戏资料导出的 530 个基础物种、208 个已实现招式、36 个野外区域，以及入门训练师、八位馆主、四天王和冠军共 14 个章节。训练师阵容、等级及融合组成来自 `Data/trainers.dat`；野外权重和等级来自 `Data/encounters.dat`；种族值、属性、学习表、成长曲线与进化关系来自本机游戏数据。

这套模式提供完整的服务端指令与结算闭环，不等同于把旧 KIF 全部地图事件和剧情脚本移植成服务端脚本。原主线和原房主联机战斗继续独立运行，不能发行受控 GOLD。受控精灵目前在受控角色内培养；现有托管精灵市场使用原有服务器资产，未增加受控精灵导入/导出入口。

## 公开规则

| 功能 | v1 规则 |
| --- | --- |
| 战斗 | 单打、最多六只队伍；服务器处理招式、PP、命中、属性、暴击、能力等级、异常状态、持续伤害、换人、伤药及挣扎 |
| 限定机制 | 关闭特性、携带物和天气；目录只发布已有处理器的招式，不把未知效果作为普通伤害执行；中性性格，无调试种族值 |
| 章节 | 只能挑战下一章；通关后提高等级上限；每章 GOLD 首次完整胜利一次，金额为该章最高对手等级 × 50 |
| 野外 | 从已解锁区域的可信权重表抽取；不接受客户端指定敌人或随机种子；野生胜利只发经验与努力值，不发 GOLD |
| 捕获 | 仅野生战斗、消耗受控精灵球；按 HP、捕获率、异常状态和服务器随机数计算摇晃；关闭会心捕获；失败也消耗球并轮到敌人行动 |
| 来源与身份 | 捕获和繁殖均新建唯一编号；捕获记录以战斗 ID 唯一，重复请求不产生第二只 |
| 经验 | 按对手基础经验与等级计算，训练师战经验乘 1.5，分给参与且未倒下的成员；使用导出的成长曲线，当前章节等级封顶 |
| 努力值 | 战斗按可信物种产出；训练每点 20 GOLD，单项 ≤252、合计 ≤510 |
| 回忆招式 | 100 GOLD；限当前物种、当前等级已解锁的公布学习表；明确替换槽位，不静默覆盖已有招式 |
| 进化 | 等级或进化石条件由服务器验证；费用 200 GOLD，道具进化另消耗对应受控石；保留精灵编号、个体值及已有招式 |
| 繁殖 | 两只兼容、未融合且非蛋的亲代；性别/蛋组/百变怪规则检查；500 GOLD；继承三项个体值，亲代进入五分钟冷却 |
| 孵化 | 服务端时间五分钟后可孵化；不接受客户端上报步数或完成时间，蛋与孵化后的精灵编号相同 |
| 融合 | 500 GOLD；两只原精灵进入占用状态，生成唯一融合体；采用项目经典融合种族值权重、属性及合并学习表 |
| 分离 | 500 GOLD；恢复两只原编号，融合体退役；融合后所得经验分配回原精灵，融合期间额外训练的努力值不复制到两只原精灵；融合体需分离后再进化或繁殖 |
| 恢复 | 精灵中心免费恢复受控 HP、PP 和状态，防止零金币且全队倒下后无法继续 |
| 放生 | 永久退役，不能放生最后一只已孵化精灵；融合体先分离 |
| 限制 | 每账号每个上海自然日最多 200 场遭遇；角色最多 180 只有效精灵；战斗最多 100 回合、30 分钟；两场开始间隔至少一秒 |

双倒下时不发章节胜利奖励。放弃、超时和回合上限也不发通关奖励；已经消费的道具和 HP 不回滚。战斗过程中锁定其他受控资产操作，不能中途训练或恢复。

## 服务端事务与恢复

`controlled_battles` 保存双方队伍、HP、PP、回合、结果、原始目录哈希和仅服务器可读的随机流。随机流由秘密 HMAC 密钥和计数器生成并持久化；网络视图不返回密钥或计数器。原始目录保存在 `controlled_rulebooks`，服务重启继续同一场战斗，不重新抽取敌人或重新结算旧回合。

每次意图要求角色版本、钱包版本；战斗还要求战斗编号和预期回合。客户端请求编号与完整参数指纹进入长期回执。不同指令并发使用同一旧版本时只有一个能成功；结果未知时用原编号恢复，不能换新编号重复提交。

HP、经验、努力值、物品消费、唯一捕获记录、章节推进、钱包、双方分录、精灵事件和回执在同一 SQLite 事务提交。任一条件或日志写入失败整笔回滚。钱包仍复用 `shop_wallets` / `shop_ledger`，没有另一套余额引擎；`campaign_reward` 为可信发行，培养、融合分离和失败扣款为回收。

`controlled_monsters` 保存当前精灵状态；`controlled_creature_events` 为追加写入事件，记录来源、前后哈希和版本。融合亲代不能作为有效精灵被再用一次。后台玩家详情提供受控章节、队伍、编号、等级、HP 与事件查询，原始战斗随机数据不暴露。

## API

所有接口使用现有注册账号 Bearer 凭据，只能访问自己的角色；不接受本地精灵、背包、胜利、奖励金额或经验数值。

| 路径 | 用途 |
| --- | --- |
| `GET /v1/controlled/adventure-catalog` | 公开规则、目录哈希、章节、区域、招式与费用 |
| `GET /v1/controlled/characters/{id}/adventure` | 当前受控精灵、队伍、进度及未结束战斗 |
| `POST /v1/controlled/characters/{id}/adventure` | 提交类型化意图 |
| `GET /admin/v1/controlled-character?id=...` | 授权后台查询与审计 |

POST 公共字段为 `request_id, expected_revision, expected_wallet_revision, rules_hash, action`。各动作额外字段：

| action | 额外字段 |
| --- | --- |
| `starter` | `species`，只能为目录初始选择 |
| `party` | `party`，1～6 个自有且已孵化编号 |
| `heal` | 无 |
| `start` | `kind` 为 `trainer/wild`，`entry` 为公布章节或区域 ID |
| `turn` | `battle_id, expected_round, command` |
| `train` | `monster_id, stat, amount` |
| `learn` | `monster_id, move, slot` |
| `evolve` | `monster_id, species`，只能是合法后继 |
| `breed/fuse` | `parents`，两个自有编号 |
| `hatch/split/release` | `monster_id` |

`command.kind` 为 `move/switch/item/catch/flee`，分别只接收已定义的槽位、精灵编号和物品字段。所有未知字段拒绝。

## 目录维护与验证

可信本地导出命令：

```powershell
& '<Ruby>' --disable-gems scripts/multiplayer/export-controlled-adventure.rb
& '<Ruby>' --disable-gems scripts/multiplayer/export-controlled-catalog.rb
```

导出器只读取安装目录中的本地 Marshal 数据；网络存档不会进入该过程。发布包携带 JSON 和哈希，不依赖服务器安装 Ruby 或 Game.exe。规则机制变更需要独立版本与对应验证，不能只改客户端奖励显示。

服务测试、真实 Ruby HTTP 和 Game.exe 验证结果见[2026-10-23 验收记录](multiplayer-evidence/admin-20261023/validation.md)。全 14 章回归使用末期等级队伍夹具，验证目录与结算状态机；它不代表从五级自然攻略的平衡测试或 Android 实机验收。
