# 训练师名片、多展示与草稿恢复

客户端：`Data/Scripts/054_Multiplayer/013_Cards.rb`；入口：`KIFMultiplayer.open_card_menu(client)`。该入口自行使用联机字体作用域，退出后恢复单机字体。

名片包含训练师昵称、好友码、注册训练师头像、最多六个展示引用，以及自愿公开的已领取纪念章。默认不公开纪念章。服务端只允许本人修改名片；展柜必须引用本人仍在发布的展示，保留选择顺序并禁止重复。下架展示或转让托管资产后，新的名片响应会排除无效引用。

头像使用服务器从可信游戏数据导出的 140 个 `TrainerType` 注册 ID 白名单。客户端进一步验证本机注册表，通过 `GameData::TrainerType.front_sprite_filename` 生成可信素材路径，再使用真实 `Sprite` / `AnimatedBitmap` 显示。网络输入不能直接指定头像文件路径；未知版本或缺失素材显示明确错误。选择界面显示训练师名称与性别，并提供实际头像预览。

徽章来自当前账号已领取的 Boss、AI 道馆、合作副本纪念章，其他奖励或初始赠送流水不会当成徽章。关闭公开时接口不返回徽章资料；客户端不靠遮挡文字隐藏。卡片不会公开凭据、恢复码、完整本地队伍或未经选择公开的个体资料。

## 独立展示与持久草稿

多展示管理使用服务端本人 active 展示列表，不再受旧界面单个 `showcase_code` 限制。发布新展示生成独立分享码；更新指定展示只增加其版本；下架一个展示不影响其他展示。成功发布仍更新旧单展示入口的最近分享码，保留原入口互通。

每次发布或更新，先将完整受限 Pokemon 快照、`public_fields`、目标分享码、所属身份和固定 `request_id` 持久保存在当前服务器的本地 profile 草稿。预览严格使用实际公开投影：默认公开物种、等级、特性、招式和受支持外观；昵称、原训练师、IV、EV 分别选择公开，隐藏昵称时同时剔除融合头部昵称。

网络失败后草稿仍可预览或重试。请求未提交或被明确拒绝时，旧公开版本不变；响应丢失时先恢复原操作，再重发相同请求编号，不能额外增加展示版本。完成后才删除草稿。退出或重启可从 profile 恢复草稿；丢弃草稿不会下架已发布版本。

服务器托管资产展示由服务器快照固定，只支持查看和下架；客户端和服务端均禁止用本地精灵更新该分享码，防止丢失托管来源和转让下架关系。用户需从托管收藏箱重新发布资产展示。

所有操作只写展示、引用及本地草稿，不提供领取或导入精灵按钮，不改变原精灵。
