# 普通本地存档：进屋音效与人物图层修复

日期：2026-10-26。用户反馈发生在普通本地存档，并确认第二个城镇也有同类现象。

## 已确认的共性原因

1. 扫描安装地图中名为 `Home door` 的入口，共有 29 个带传送的入口页，其中 9 个页没有音效指令或带音效的移动路线。包含真新镇、常磐市及其变体地图。现由共用 `Game_Event#start` 为这些入口播放现有 `Entering Door.wav`，已有音效的门保持自己的事件流程。重复启动同一待执行事件不会重复播音。
2. 玩家身体在 `Sprite_Character#update` 后半段更新坐标、深度和可见性，头发、帽子却在前面的位图查询中定位，造成一帧滞后；其旧滚屏补偿又额外偏移 8 像素。现统一在身体更新完成后定位，删除重复补偿。
3. 玩家进门隐藏或淡出时，头发、帽子的独立 Sprite 没有同步可见性和透明度。现同步这两项状态，避免身体隐藏后留下头部图像。

缺音效入口（地图编号、事件编号）：

| 地图 | 事件 |
| --- | --- |
| 1 | 3 |
| 42（真新镇） | 4、5 |
| 79（常磐市） | 1、72 |
| 710 | 1、72 |
| 711 | 1、72 |

修复作用于共享代码，没有重写地图事件、传送坐标或玩家存档格式。

## 第二轮：剩余遮挡和动作切换顿挫

同日继续处理普通本地存档，已修复：

- **屋檐/门框前露出帽子**：身体的图层深度通常只比上方图块低 1，而头发/帽子原来另加 1、2。现在整个人物使用相同深度，由 RGSS1 的创建顺序排列身体、头发、帽子，不跨越环境图块的深度。原生像素断言验证了屋檐遮挡整个角色，以及移去屋檐后帽子仍位于头发/身体上方。
- **草丛里丢失服装**：玩家的草丛遮罩原来取未合成衣服的底图；现在取穿衣后的动作图。NPC 保持原路径。原生测试比较了实际服装像素，确保脚部遮罩上方的衣服不被替换成底图。
- **反复步行/跑步切换时重复解码与合成**：当前外观的动作图和底图各保留一份所有权引用。底图缓存能在地图切换清理 RPG 缓存后继续正确使用；换肤、染色、换装和刷新会失效重建，退出场景会释放。
- **资源释放不完整**：删除未使用的克隆，用正确重置引用计数的 `copy` 创建独占合成图，释放临时服装源图；替换或移除头发/帽子时也释放旧资源。图片解码失败保留仍可用的旧图层。

没有改变行走速度、碰撞判定、游戏逻辑帧率或存档格式。

### 首次安装/升级后的资源等待

安装最终包时观察到解压速度过慢，进一步确认默认 ZIP 解压流使用 512 字节缓冲，造成大量 AssetManager/解压层小块读取。现在使用 256 KiB 的有界输入、解压和回退缓冲；没有改动路径校验、文件 SHA256、解压大小限制、ZIP 完整性校验、原子提交、逐文件同步或失败恢复规则。

`PayloadArchiveHostTest` 新增不可压缩的大文件及相邻 ZIP 条目用例：原实现不能满足底层读取次数上限，修复后 2 MiB 用例仅 9 次底层读取。同时将每个摘要逐字节调用 `String.format` 改为共享的定长十六进制编码，避免两万多个资源校验时大量创建格式化对象；覆盖全部 256 种字节值及前导零，摘要内容不变。该生产实现的 **38 项断言在主机和 Android 实际运行时全部通过**，且已加入日常主机检查。此优化改善安装、升级首次启动，不计作地图游戏帧率提升。

专用模拟器曾从同一签名 APK 的 payload 预展开规范文件来缩短虚拟磁盘准备；没有手动创建完成标记，仍要求生产安装器验证全部文件后才能进入包内回归。因此该次属于恢复安装路径验收，不宣称空白设备首次安装耗时已验收。
