# 交易中心：托管精灵、道具与社交交易封测

本功能在特性分支 `codex/trading-center` 开发。精灵来源、币种与本地休闲交换分开；这里的精灵保存在服务器收藏箱，道具保存在联机库存，暂不进入主队伍、PC 或主线背包。主线资产接入属于后续阶段。

## 玩家入口与流程

从标题选择在线模式并注册／登录账号，暂停菜单直接选择「交易中心」或宝可梦中心 PC 的「全球交易市场」。原「联机 → 交换与托管收藏 → 交易中心（市场／钱包）」入口保留。历史恢复码身份可以继续原有玩法，新市场要求注册账号。

- 全球精灵市场：搜索、筛选、排序、查看详情并购买。支持等级、价格、性格、性别、双特性、六项 IV 下限／精确值、31 IV 数量、融合头部／身体等条件。每页 20 条。
- 全球道具市场：按名称／ID 搜索，明确显示每件单价、数量与整单总价；每单最多 9,999 件，首版只支持整单成交。
- 出售精灵：只允许未占用的服务器托管资产。每账号最多 10 单，期限 7 天。
- 我的挂牌：查看近期挂牌；在售商品可撤单。买家购买后卖家联机币直接到账，卖家无需在线。
- 面对面交易：输入好友码，或通过暂停菜单「附近玩家」向同地图五格内玩家发起邀请；对方接受后每方最多选择 6 只精灵、8 种道具和一笔金额。双方锁定，等待 3 秒，再分别最终确认。任一清单变化清除双方旧确认。
- 待领取：购买、撤单或到期的精灵留在服务器交付容器；领取只收纳已有资产。重复领取、重启和换设备都不生成第二只。
- 恢复断线操作：先查询原请求编号，再恢复原结果；网络超时不代表成交失败。
- 联机道具：查看实际、可用和占用数量。上架、交易报价与待领取共用数量预留；本地背包不能上传或兑换为联机库存。
- 交易邀请设置：关闭附近／好友码邀请，按好友码屏蔽或取消屏蔽；地图 HUD 提示收到的邀请。邀请仅发给当前接收者，每个发起者每分钟最多五次。

聊天界面新增交易频道，方向左键或「交易商品」按钮查看最近商品卡。卖家可从挂牌详情分享自己仍在售的商品。卡片只保存挂牌编号与展示摘要，打开时重新查询真实价格和状态；旧卡片不能购买已经成交／撤回的商品。旧构建的世界聊天客户端不接收其不支持的新频道消息。

上架费为整单价格的 2%，向上取整，最低 100、最高 25,000 联机币；撤单和到期不退费，成交不另收费。例如售价 50,000，上架扣 1,000，售出到账 50,000，净收益 49,000。

面对面邀请 30 秒失效，接受后空闲 3 分钟、会话最长 10 分钟。超时释放未成交的资产和金额；已经成交的结果保留查询。单向赠送允许，双方均为空禁止。

预览显示实际 IV／EV、招式、双特性和原训练师，使用标准素材及保存的闪光参数；本阶段没有玩家自选替代立绘交易。缺少对应标准素材时阻止购买确认，需先安装素材。交易预览独立读取素材，不调用会修改主世界立绘选择缓存的原展示流程。

## 钱包与测试资产

钱包币种为 `LINK`（界面显示联机币），每账号统一管理，可用余额扣除所有未完成交易的预留金额。金额为整数，余额上限 9,999,999,999。联机币不能从本地金币、云存档金钱字段或客户端胜利报告充值。

默认新账号钱包为零；封测资产与额度由运营者离线发放，没有公开的发币／导入资产接口。每次发放指定全局唯一事件 ID，重复执行相同事件返回原结果；相同 ID 改参数会拒绝。测试额度不能直接沿用为正式服经济。

先停止对应服务，再执行下列命令；这些管理命令会取得数据库实例锁，不能并行修改运行中的服务数据库。路径中的 Python 使用本机已安装的 Python 3。

```powershell
python server/multiplayer/trading_admin.py --database <独立封测数据库> grant --username <已注册账号> --event-id beta_batch_001 --coins 200000 --catalog-slots 0 1 2 --items POTION=20 RARECANDY=5
python server/multiplayer/trading_admin.py --database <独立封测数据库> audit
python server/multiplayer/trading_admin.py --database <独立封测数据库> pause
python server/multiplayer/trading_admin.py --database <独立封测数据库> resume
```

目录槽位指向服务端已安装的真实游戏验证目录。道具只认可 `catalog-trading-items-v1.json` 中经真实游戏注册表导出的 36 种非绑定道具；缺失的别名不进入白名单。客户端无法上传模板或库存发放资产。发放记录、精灵归属、钱包与道具借贷分录同事务保存。

## 生产升级与恢复

生产数据库元数据版本升级为 3；支持从版本 1／2 添加式迁移。新部署通过原初始化入口创建全部表；旧生产数据库须先停服，使用本版本管理命令执行添加式迁移：

```powershell
python server/multiplayer/trading_admin.py --database <旧数据库> migrate --backup <尚不存在的一致性备份路径>
```

迁移先使用 SQLite backup API 保存完整旧库，再初始化新增表、核对钱包账本并更新部署版本。保留原账号、云存档、交易、收藏箱和其他玩法记录；不重建或清空数据库。旧版本备份保留原部署版本，回退须配套旧代码；新生产入口拒绝未迁移数据库。

资产以编译物种／招式／道具／特性／属性数据、Mods 与序列化规则生成语义指纹，客户端界面源码更新不改变该指纹。旧资产通过已安装且哈希吻合的可信目录历史补齐指纹，保持原编号和全部属性；缺少可信来源的记录不自动升级。实际玩法数据变化会停止旧挂牌并退回资产，未提交的旧构建直接交易取消并释放预留。迁移结果输出已补齐及未识别资产数，便于处理更早目录。

服务端上线使用现有生产适配器的 `synchronous=FULL`，并继续一致性备份。暂停市场会阻止新增挂牌、购买、邀请、报价和确认；历史查询、撤单、取消及既有交付领取仍可使用。

## 事务和接口约定

- 市场、原托管交换、交换池、新直接交易及交付共用一套资产锁。
- 购买同时完成扣款、卖家收款、唯一归属转移、挂牌终态、交付、审计事件和幂等回执。
- 直接交易预留金额和资产，最终核对版本、完整报价哈希及当前所有权后一次提交；双方给钱时按净变化结算，避免临时余额溢出。
- 经济写入沿用 `Client` 的持久化请求日志。搜索使用只读 `POST /v1/market/search`，不会占用经济操作日志；现有服务仍拒绝查询字符串。
- 领取只解除对应交付锁，历史领取记录不能重新分配后来已转手的资产。
- 道具购买在同一事务内转移实际数量，并预留买家的待领取数量；领取不增加实际数量。道具下架或停止开放时，撤单和领取仍能退回原数量。
- 本地休闲精灵、导入副本、客户端展示缓存与旧云存档不能覆盖服务器钱包或资产所有权。
