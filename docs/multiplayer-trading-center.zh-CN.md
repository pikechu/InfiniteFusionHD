# 交易中心与托管在线角色

本功能在特性分支 `codex/trading-center` 开发。精灵市场、道具市场、组合交换和托管在线角色已实现。服务器托管资产可以进入独立在线角色的队伍、联机 PC 和背包；钱包、归属和培养结果由服务器保存。原本地角色与休闲资产保留独立来源。

2026-10-23 补充特殊剧情战和活动适配，数据库版本为5。最新验证范围及构建记录见文末「特殊战与 Android 跨端验证记录」；前面的阶段记录保留对应历史构建。

## 玩家入口与流程

从标题选择在线模式并注册／登录账号，暂停菜单直接选择「交易中心」或宝可梦中心 PC 的「全球交易市场」。原「联机 → 交换与托管收藏 → 交易中心（市场／钱包）」入口保留。历史恢复码身份可以继续原有玩法，新市场要求注册账号。

- 全球精灵市场：搜索、筛选、排序、查看详情并购买。支持等级、价格、性格、性别、双特性、六项 IV 下限／精确值、31 IV 数量、融合头部／身体等条件。每页 20 条。
- 全球道具市场：按名称／ID 搜索，明确显示每件单价、数量与整单总价；每单最多 9,999 件，首版只支持整单成交。
- 出售精灵：只允许未占用的服务器托管资产。每账号最多 10 单，期限 7 天。
- 我的挂牌：查看近期挂牌；在售商品可撤单。买家购买后卖家联机币直接到账，卖家无需在线。
- 面对面交易：输入好友码，或通过暂停菜单「附近玩家」向同地图五格内玩家发起邀请；对方接受后每方最多选择 6 只精灵、8 种道具和一笔金额。双方锁定，等待 3 秒，再分别最终确认。任一清单变化清除双方旧确认。
- 待领取：购买、撤单或到期的精灵留在服务器交付容器；领取只收纳已有资产。重复领取、重启和换设备都不生成第二只。
- 恢复断线操作：先查询原请求编号，再恢复原结果；网络超时不代表成交失败。
- 联机道具：查看实际、可用和占用数量。上架、交易报价与待领取共用数量预留；本地背包不能上传或兑换为联机库存。
- 交易邀请设置：关闭附近／好友码邀请，按好友码屏蔽或取消屏蔽；地图 HUD 提示收到的邀请。邀请仅发给当前接收者，每个发起者每分钟最多五次。

聊天界面新增交易频道，方向左键或「交易商品」按钮查看最近商品卡。卖家可从挂牌详情分享自己仍在售的商品。卡片只保存挂牌编号与展示摘要，打开时重新查询真实价格和状态；旧卡片不能购买已经成交／撤回的商品。旧构建的世界聊天客户端不接收其不支持的新频道消息。

上架费为整单价格的 2%，向上取整，最低 100、最高 25,000 联机币；撤单和到期不退费，成交不另收费。例如售价 50,000，上架扣 1,000，售出到账 50,000，净收益 49,000。

面对面邀请 30 秒失效，接受后空闲 3 分钟、会话最长 10 分钟。超时释放未成交的资产和金额；已经成交的结果保留查询。单向赠送允许，双方均为空禁止。

预览显示实际 IV／EV、招式、双特性和原训练师，使用标准素材及保存的闪光参数；本阶段没有玩家自选替代立绘交易。缺少对应标准素材时阻止购买确认，需先安装素材。交易预览独立读取素材，不调用会修改主世界立绘选择缓存的原展示流程。

## 钱包与测试资产

钱包币种为 `LINK`（界面显示联机币），每账号统一管理，可用余额扣除所有未完成交易的预留金额。金额为整数，余额上限 9,999,999,999。联机币不能从本地金币、云存档金钱字段或客户端胜利报告充值。

默认新账号钱包为零；封测资产与额度由运营者离线发放，没有公开的发币／导入资产接口。每次发放指定全局唯一事件 ID，重复执行相同事件返回原结果；相同 ID 改参数会拒绝。测试额度不能直接沿用为正式服经济。

先停止对应服务，再执行下列命令；这些管理命令会取得数据库实例锁，不能并行修改运行中的服务数据库。路径中的 Python 使用本机已安装的 Python 3。

```powershell
python server/multiplayer/trading_admin.py --database <独立封测数据库> grant --username <已注册账号> --event-id beta_batch_001 --coins 200000 --catalog-slots 0 1 2 --items POTION=20 RARECANDY=5
python server/multiplayer/trading_admin.py --database <独立封测数据库> audit
python server/multiplayer/trading_admin.py --database <独立封测数据库> pause
python server/multiplayer/trading_admin.py --database <独立封测数据库> resume
```

目录槽位指向服务端已安装的真实游戏验证目录。可交易道具以 `catalog-trading-items-v1.json` 中真实游戏注册表导出的非绑定白名单为准，包含已适配的消耗品、进化道具和携带物；缺失的别名不进入白名单。客户端无法上传模板或库存发放资产。发放记录、精灵归属、钱包与道具借贷分录同事务保存。

## 生产升级与恢复

生产数据库元数据版本升级为 5；支持从版本 1／2／3／4 添加式迁移。新部署通过原初始化入口创建全部表；旧生产数据库须先停服，使用本版本管理命令执行添加式迁移：

```powershell
python server/multiplayer/trading_admin.py --database <旧数据库> migrate --backup <尚不存在的一致性备份路径>
```

迁移先使用 SQLite backup API 保存完整旧库，再初始化新增表、核对钱包账本并更新部署版本。保留原账号、云存档、交易、收藏箱和其他玩法记录；不重建或清空数据库。旧版本备份保留原部署版本，回退须配套旧代码；新生产入口拒绝未迁移数据库。

资产以编译物种／招式／道具／特性／属性数据、Mods 与序列化规则生成语义指纹，客户端界面源码更新不改变该指纹。旧资产通过已安装且哈希吻合的可信目录历史补齐指纹，保持原编号和全部属性；缺少可信来源的记录不自动升级。实际玩法数据变化会停止旧挂牌并退回资产，未提交的旧构建直接交易取消并释放预留。迁移结果输出已补齐及未识别资产数，便于处理更早目录。

服务端上线使用现有生产适配器的 `synchronous=FULL`，并继续一致性备份。暂停市场会阻止新增挂牌、购买、邀请、报价和确认；历史查询、撤单、取消及既有交付领取仍可使用。

## 事务和接口约定

- 市场、原托管交换、交换池、新直接交易及交付共用一套资产锁。
- 购买同时完成扣款、卖家收款、唯一归属转移、挂牌终态、交付、审计事件和幂等回执。
- 直接交易预留金额和资产，最终核对版本、完整报价哈希及当前所有权后一次提交；双方给钱时按净变化结算，避免临时余额溢出。
- 经济写入沿用 `Client` 的持久化请求日志。搜索使用只读 `POST /v1/market/search`，不会占用经济操作日志；现有服务仍拒绝查询字符串。
- 领取只解除对应交付锁，历史领取记录不能重新分配后来已转手的资产。
- 道具购买在同一事务内转移实际数量，并预留买家的待领取数量；领取不增加实际数量。道具下架或停止开放时，撤单和领取仍能退回原数量。
- 本地休闲精灵、导入副本、客户端展示缓存与旧云存档不能覆盖服务器钱包或资产所有权。

## 托管在线角色

从「交易中心 → 托管角色／培养」创建角色，先将精灵放入联机队伍，再选择「进入主线角色」。当前角色先原子保存并上传；新角色使用另一个空手动槽。原队伍、本地道具和金币不兑换为联机经济。普通 PC 可选择联机队伍／PC 或保留的休闲存储；休闲存储的修改不消耗联机库存。

每账号首次创建发放一只等级5初始精灵、1000 LINK、5伤药和10精灵球，均有唯一发放事件。后续角色共享账号库存，不重复发放。买入／领取的资产可从联机 PC 加入队伍；旧目录资产首次使用需在角色界面「准备」完整数据，保留既有属性。上架、交换和释放前必须存入联机 PC，队伍中的资产不能被交易锁占用。

角色界面提供等级、EV、合法学招、等级／道具进化、交易进化预览、融合／拆分、繁育、孵化、回复和释放。融合托管两个原资产身份，拆分按来源链恢复；携带物占用独立的道具账本桶，不能同时出现在背包。释放归档精灵并退回携带物。繁育由原生孵蛋算法生成蛋的蓝图，亲本保留；支付2000 LINK，服务器孵化准备时间5分钟。重复孵化只返回同一资产编号。

经典交易进化按本项目已安装的进化图适配；例如蚊香君携带王者之证的交易预览显示蚊香蛙皇及携带物消耗。最终变更由唯一成交事件排队执行，客户端重播动画不会再次进化。新组合交换、原托管交换和托管奇迹池均接入此事件；引擎未启用的收藏封测服不执行主线进化。

普通野生战斗、已安装训练师和已适配的固定脚本遭遇由服务器运行真实战斗引擎。客户端通过文字战斗菜单选择招式、换人、精灵球、治疗或撤退；服务器计算随机数、伤害、捕获、经验、携带物和金钱变化。队伍、战斗资源和结果同事务结算。训练师奖金按角色唯一事件发放，重复挑战不再次发钱。联机徽章挑战按顺序开放，等级上限为20加每枚已验证联机徽章10级，最多100级。联机徽章是独立进度，不读取本地剧情徽章作为经济资格。

普通背包治疗、培养、进化道具、携带物给予／取回、全队回复和商店入口已接入托管流程。在线补给按服务端当前单价购买，价格为0或未开放的道具不出售。野生战斗的道具按实际消耗结算，无效治疗会返还。钱包达到上限的可信奖金进入待收款，可在角色首页分次领取。

旧云存档只包含角色与资产引用。每次加载及安全地图轮询都会重新投影服务器归属、属性、钱包和背包，较旧的异步响应不能覆盖更新版本。本机 IV／EV 等单机选项不改变托管数值；本地奖励保留休闲来源。另一设备必须通过现有云写租约登录并刷新经济状态，不能将旧队伍或旧余额写回账本。

加载时先隔离旧经济投影，再用一个只读同步请求同时取得角色和库存。首次同步失败会保留空的不可用投影并抛出错误，连接恢复后可重试；不会在后台同步和前台加载交错时接受旧队伍、旧余额或半完成的云快照。

客户端断线后用原请求／任务编号恢复，运行中的战斗会等待指令，超时自动撤退／合法换人。服务重启对未结算任务保留原属性并释放预留，不接收旧引擎结果；已经结算的任务只读恢复。交易进化事件在重启后重新排队且只结算一次。

## 启用原生权威引擎

市场和收藏服务器不要求原生运行时。在线主线当前需要 Windows 上可运行的完整 Game.exe 游戏目录，客户端 Windows／Android 仍使用同一 HTTP 协议。现有 Linux 服务部署包只包含服务器代码，不包含游戏运行时；不得把部署包本身当作可直接运行主线的 Linux 引擎。

先在匹配客户端的完整游戏目录重建清单与可信目录，再为服务器进程设置路径：

```powershell
& scripts/multiplayer/rebuild-native-catalog.ps1 -PythonExecutable <Python路径>
$env:KIF_MAINLINE_GAME_ROOT = 'D:\games\kurayshinyrevamp'
python server/multiplayer/service.py --database <已迁移的独立数据库> --port 18812
```

原生工作代码来自当前服务器发布包；游戏目录提供编译数据与相同版本客户端脚本。每个任务使用私有隔离目录与隐藏进程，不读取玩家存档。私有 HMAC 密钥、nonce 和有界 JSON 请求／结果用于校验本实例的工作结果；公共 API 不提供提交战果、上传属性、上传脚本或直接发币的入口。失败／超时只终止本实例持有的进程对象，不能根据磁盘 PID 杀进程。备份仍必须整库一致；引擎临时目录不作为资产来源恢复。

常用接口为 `/v1/mainline/config`、`/characters`、`/characters/{id}/party`、`/characters/{id}/pc/search`、`/characters/{id}/jobs`、`/jobs/{id}`、`/jobs/{id}/commands`、`/shop`、`/shop/buy`、`/eggs`、`/eggs/{id}/hatch`、`/credits/claim` 与 `/assets/{id}/release`。所有经济写入沿用账号范围的幂等请求编号；角色与资产均检查当前归属。
