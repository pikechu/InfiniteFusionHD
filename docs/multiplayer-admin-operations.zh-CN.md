**KIF 运营后台使用与开发验收**

特性分支：`codex/admin-operations`。设计依据：[后台统计与玩家管理方案](multiplayer-admin-statistics-plan.zh-CN.md)。

当前已实现独立管理员登录与 TOTP、权限检查、玩家搜索与详情、在线及账号活跃统计、异步存档摘要、封禁/禁言/踢线/交易冻结、管理备注和操作审计。后台直接使用当前游戏服务实例；查询使用单独的只读连接，存档解压在后台任务中进行。

经济后台复用商城/市场的 `shop_wallets` 和 `shop_ledger`，由数据库触发器在同一事务写双方分录。新增钱包调整、金额和状态版本检查、独立管理员复核、发行/销毁/系统保有分类、流水查询和对账。真实支付没有接入。

另外已实现按首次观察到的游戏活动计算留存、风险案件与证据版本、异步 CSV 导出、批量活动调整、云档历史版本、人工角色归并，以及维护期间的主线金币快照修复。

按已确认的「新建受控角色」策略，另外交付独立 GOLD 钱包、服务器库存、账号初始发放、签到与 NPC 买卖。2026-10-23 继续交付[受控主线 v1](multiplayer-controlled-mainline.zh-CN.md)的章节战斗、捕获与培养服务端结算；游戏在线暂停菜单提供入口，旧存档资产不导入。后台首页显示受控 GOLD 总量和当日产出/回收，玩家详情可查询章节、精灵和来源事件。

「商城与市场运营」支持暂停/恢复新业务、商品上下架与调价、订单退款复核、兑换码申请/激活/停用及异常挂牌撤销。退款同时退点券和撤销订单权益；取消挂牌释放原资产锁。兑换码和退款均要求独立复核，兑换码明文只在申请者的创建表单显示，不写入数据库或审计；停用待激活码会同时撤销其激活申请。

**本地启动**

使用 Python 3.11+，先启动一次升级后的联机服务，确认数据库已创建管理表。已有生产数据库通过正常受保护的服务入口升级；不要为启动后台构造第二个 `Store`。

```powershell
& '<Python>' server/multiplayer/service.py --database '<本地测试数据库绝对路径>'
```

另开终端创建管理员。该工具直接打开已有数据库，不执行游戏服务启动恢复；密码从交互输入读取，不写在命令行。角色可以选 `observer`、`gm`、`operator`、`admin`。

```powershell
& '<Python>' server/multiplayer/admin_cli.py --database '<同一数据库绝对路径>' --username operator --role admin
```

将终端返回的 `otpauth://` 信息加入身份验证器，妥善保存恢复资料，保持终端私密。浏览器访问 `http://127.0.0.1:8765/admin/`，使用管理员账号、密码与六位动态验证码登录。验证码不可重复使用，会话有效一小时；刷新整个浏览器页面需要重新登录。工具没有预设生产账号或默认密码。

禁用管理员会同时撤销其全部管理会话：

```powershell
& '<Python>' server/multiplayer/admin_cli.py --database '<同一数据库绝对路径>' --username operator --disable
```

生产发布包包含后台模块和静态资源；Caddy 配置已包含 `/admin` 与 `/admin/*`，生产适配器仍要求可信本机代理提供客户端地址。实际升级和发布需要按已有部署流程执行，本次开发不自动修改公网服务。

**功能口径**

- 当前在线为 20 秒内有有效游戏世界心跳且仍有有效账号会话的去重注册账号；登录 token 数不等于在线人数。历史临时身份另外统计。
- DAU、WAU、MAU 基于接入后的有效游戏活动，按 Asia/Shanghai 日期去重；没有接入前的完整历史。在线时长是心跳观察区间，单次最多累计 20 秒，不冒充精确游玩时长。
- 存档摘要关联上传 revision、哈希和提取器版本，当前提取训练师名、训练师编号、金币、队伍数量和徽章数量。格式异常显示无效，未知值不计为零。摘要来自不可信客户端快照。
- 未人工归并的多存档与备份不直接累加成“全服总金币”。服务端 GOLD、联机币和点券分别按账本汇总。
- 管理操作要求原因、唯一指令编号和玩家状态版本；重复请求不重复执行，状态变化后需要重新审阅。封禁和踢线撤销游戏凭据、云租约及在途分片；封禁也拦截登录和旧恢复码。
- 普通钱包调整必须同时满足钱包 revision。单笔绝对值超过 10,000 或当日累计超过 100,000 时进入待复核，需另一名有经济权限的管理员执行，申请有效期一天；执行时重新检查钱包和玩家状态。
- 商城消费进入系统保有账户，管理员扣回进入销毁账户，市场买卖通过清算账户相抵。真实支付、点券消费和玩家成交额分别解释。未知历史流水来源进入未分类告警，不能视为正常发行。
- 收支支持今日、昨日、近 7 天、近 30 天及最多 90 天自定义区间；与上一等长区间比较。包含今日时，上期只算到对应时刻，避免把当天未结束的产出与完整一天混比。采集未覆盖完整历史时显示已保留记录并停用增长率。余额、对账和排行榜仍是当前状态；流水和 CSV 使用所选区间。
- 原始经济流水不可通过 UPDATE/DELETE 修改。管理员查询、成功操作和已认证的拒绝记录均可在审计中检索；秘密凭据与动态验证码不入审计。
- 批量调整接口支持最多 100 个目标钱包，网页一次最多 50 个；同一批次不可重复钱包（GOLD 按角色，其余按账号），必须独立复核。执行前核对全部目标的玩家状态和钱包版本，同一事务完成发放与审计，任一失败整批回滚。发起人权限被撤销后，待复核申请不再可执行。
- 风险检测保留对账差异、未知流水来源、清算差异、资产归属差异及集中发行证据。案件处理与证据分别有版本，证据变化需要重新审阅，不自动封禁账号。
- CSV 由后台队列读取一致性快照，每份最多 5,000 行、4 MiB，只允许创建人凭当前导出权限下载，结果 24 小时后清除；文本进行公式注入防护，超限明确失败，不静默截断。
- 导出任务列表保留各任务自己的币种和日期，切换页面筛选不会改变旧文件；预设日期在提交时固定，排队跨过午夜也不改变原区间。
- 存档摘要使用持久队列按 revision 增量提取；重启和中途再次上传不会让旧摘要覆盖新版本。首次活跃索引避免每次留存查询扫描全部历史活动；在线峰值在加入世界时记录，并在同步期间按秒采样。

**角色归并与存档维护**

玩家详情可把经人工确认属于同一角色的多个槽位归入服务器生成的 `char_...` 标识，并选择一个当前统计槽位。总览显示这批已归并角色的金币快照金额、覆盖数量和未归并槽位数；数据依然标记为客户端快照，不计入可信联机币总额。不以训练师名或训练师编号自动判断角色相同。

存档每次成功上传时保留历史：每个槽位至少保存最近三份版本，以及最近七天的每日最新检查点。该功能接入前不存在的历史不能追溯生成。修复前版本会额外固定保留，原始云档内容不进入公开接口。KIF 同时保存当前 `:kuray_player` 和原版兼容 `:player`，摘要优先读取当前玩家，修复同步更新两份视图；提取器升级会重新排队生成旧摘要。

修复流程为「开始存档维护 → 核对目标槽位与版本 → 预览修复 → 确认执行 → 查看摘要与历史 → 结束维护 → 玩家重新登录」。若仍有有效云写入会话，默认拒绝开始维护；管理员可在预览中明确选择强制撤销，未上传进度可能需要从玩家本机恢复记录另行处理。

维护状态持久化并拦截玩家登录及旧会话写入，不能只删除地图在线状态。当前修复器仅允许修改受限 JSON 图中 `Player` 的金币字段，使用本游戏的 0～999,999 上限；解压、白名单检查和新快照生成在游戏写锁之外进行，提交时再次比较 revision、校验和、维护会话和管理状态版本。成功后版本递增，旧上传不能覆盖修复结果。此操作不修改服务端钱包、托管精灵、商城权益或订单。

后台表建立后带有独立 schema 标记；发现关键审计、凭据、控制或经济表缺失会停止启动，要求恢复日志，不把缺失的业务表静默重建为空。

**整档回滚与独立复核**

玩家进入存档维护后，可读取槽位历史版本，预览「当前版本 → 新版本，内容来自历史版本」并提交整档回滚申请。另一位有经济权限的管理员核对源版本、校验和、快照金币和可信资产保留范围后执行。申请有效一天；申请人不能自批，申请人权限撤销后不能继续执行。

回滚只替换指定槽位的完整历史云档，始终写成更大的新 revision。受控 GOLD、背包、精灵、主线进度、托管资产、商城、交易和当前所有权不恢复到过去。申请及执行时对当前管理版本、维护会话、云档与来源校验和、钱包版本和资产状态哈希做检查；任一变化都拒绝旧预览。源快照在游戏写锁外安全解析，不执行 Ruby；来源和回滚前版本固定保留。回滚、状态版本、指令回执及审计同事务提交。

同账号只允许一份有效待复核申请。申请人或系统管理员可取消；待复核时不能直接结束维护。完成或取消后，刷新详情再结束维护，玩家用新凭据重新登录并拉取新版本。云档不受支持或持有超过 1,000 只托管资产时拒绝在线整档回滚，改用独立离线恢复流程；不会静默跳过资产检查。

管理动作：`request_save_rollback`、`approve_save_rollback`、`cancel_save_rollback`；列表为 `GET /admin/v1/save-rollbacks?target=...`。这些操作不能通过回档重新铸造受控资产。

**进阶市场价格分析**

「市场价格分析」仅使用 MARKET 的已核对成交。`market_sales` 以挂牌编号唯一，并核对卖方成交回执、买方扣款与卖方入账；同一成交的双回执和请求重试只计一次。历史可验证记录支持一次性回填，不完整历史单列缺口并进入调查，原始成交日志禁止更新或删除。

支持最多 90 天的区间、物种/融合编号、等级、异色和原始个体值总和筛选。报表提供成交额、笔数、均价、中位价、P10/P25/P75/P90、独立资产/买家/卖家数、成交等待时间与每日趋势，分位数使用最近秩法。分组按物种、十级区间、异色和 IV 档位；样本充足需至少五笔、三只独立资产和三名买家。特性、性格和招式差异仍可能影响价格，不把统计中位数称为精灵的确定价值。

当前有效挂牌数量与挂牌中位价独立展示，不计入成交额。单个区间超过 10,000 笔要求缩小筛选；最多展示成交额前 100 组并显示总组数。成交 CSV 与页面筛选一致，使用原有 5,000 行/4 MiB/24 小时限制，任务列表保留自己的条件。报表接口为 `GET /admin/v1/market-prices`，导出任务类型为 `market_sales`。

新增成交日志缺口、同资产一小时内往返、同组五倍价格偏离和新账号集中购买线索。价格偏离至少需要六笔、三只独立资产、三名买家，并排除自身成交计算同组中位数；集中购买门槛为七日内注册账号、24 小时至少五笔且总额至少 100,000。均为带规则版本的调查证据，不自动封号。
