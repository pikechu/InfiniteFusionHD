# 离线资源下载与更新

开始菜单提供“一键下载完整离线资源”。资源管理页可下载、更新、重试、完整性校验或手动检查更新。资源数量和大小以资源管理页为准，覆盖 IF 基础/自定义融合/自动融合图集、蛋与特殊立绘、基础与融合索引、作者名单、图鉴源数据（额外中文说明随相应语言资源包提供）。原游戏已有的独立 PNG、地图、音频和其他素材继续随游戏安装。

首次启动仅检查游戏版本和资源清单，每次进程最多检查一次资源更新。GitHub Actions 每天北京时间 11:23、23:23 自动检查官方资源，也可在 Actions 页面手动运行。已安装的资源包有新版本时会提示，开始菜单显示“有更新”。检查失败不阻止单机游玩；资源页可用游戏附带或上次通过校验的清单继续下载。版本和资源检查均不再下载、执行远程 Ruby 配置。

下载按文件显示数量和字节进度，可按返回键取消。已验证文件及记录会保留，下次仅补齐缺件和变更文件。每个文件在写入前验证长度、SHA-256（辅助数据）或 Git blob SHA-1（上游图片），图片还检查 PNG 头及尺寸。下载先写同目录临时文件再原子替换，失败保留旧文件。失败清单在 `Data/offline-resources/failures.json`。完整性校验会重新计算所有文件的校验值，不访问网络；只在全部通过时标记完整。

成功后选择 Local 图集并保留“下载数据”开启。游玩中使用本地素材，图鉴立绘页不再批量探测远程变体。真正缺少的素材仍可按需下载：清单内文件按清单校验；清单尚未包含的新图集沿用 HTTPS 源并验证 PNG/尺寸。失败的素材在同一进程不反复尝试；资源菜单可重试。玩家手动关闭“下载数据”后，按需补图也会关闭。

缓存和校验记录位于 `Data/offline-resources/`，图片安装到原有图集目录，裁切缓存沿用现有图集实现。自定义图鉴源文件单独缓存为 `dex-source.json`，更新合并到活动图鉴时保留本地作者条目。不会修改玩家存档或自动清理自定义独立 PNG。

## 维护与发布

- 工作流：`.github/workflows/sync-upstream-resources.yml`。同步官方 `pif-downloadables` 的立绘索引、`pokedex-entries` 的图鉴说明，以及官方 CDN 的作者名单和当前游戏支持的基础/融合图集；同时重新检查 IF GitHub 的自动融合、蛋和特殊立绘。只接收当前 `NB_POKEMON` 与图集尺寸支持的内容。
- 所有上游内容先在临时运行环境下载并验证，再一次提交数据和清单到 `main`。不执行上游脚本、不修改游戏规则、不删除本地扩展说明或独立 PNG。无变化时不提交；网络错误、尺寸不兼容或容量超限时整次同步失败，旧资源继续可用。
- 图集通过小范围 PNG 头请求和 ETag 检测变化，仅对变化图片完整下载并计算 SHA-256。`Data/upstream-resource-state.json` 保存官方 CDN 的 ETag，不保存访问凭据或玩家数据。图片由客户端从官方 CDN 下载，Git 仓库不保存整套图片。
- 最新图鉴说明超过旧客户端 8 MiB 下载上限，发布为 `Data/pokedex/dex.json.gz`；客户端校验压缩包后有界解压、合并到本地说明，最多 32 MiB/100,000 条。查看图鉴复用本地索引，不反复解析整份说明。此格式需要 0.20.8 或更新客户端；旧客户端会保留旧清单并提示游戏更新。
- Actions 使用仓库自带 `GITHUB_TOKEN`，仅请求内容写权限，不需要用户 PAT。仓库若以后保护 `main` 并禁止机器人直接提交，应调整为经过仓库规则允许的发布流程，不绕过保护。GitHub 定时运行可能延迟，公开仓库连续 60 天没有活动时可能自动停用，需要从 Actions 页面重新启用。

- 项目地址统一为 `https://github.com/pikechu/InfiniteFusionHD`，游戏版本、资源清单、神秘礼物和 Windows 更新目标均使用 `main`。资源图片固定到 IF 源仓库的具体提交，辅助数据由本仓库维护。
- 更新 IF 资源清单：运行 `python scripts/resources/build_manifest.py`。它只读取 GitHub 文件目录和校验值，不下载 1.22 GB 图片。网络或目录截断会失败，不发布不完整清单。
- 仅修改本地图鉴或索引后：运行 `python scripts/resources/build_manifest.py --refresh-data`，重新计算辅助文件校验值，不访问网络。
- 将 `Data/offline-resources.json` 与对应的辅助文件一起提交、发布到 `main`。清单若先于对应文件发布，客户端会拒绝哈希不匹配的下载并提示重试。新资源提示以本仓库发布的清单为准，不在游玩中扫描第三方仓库。
- Windows 包含 `Data/resource-download.ps1`、更新批处理及其 Git 工具。桌面下载使用独立、隐藏的 PowerShell HTTPS 进程，不在 Ruby 工作线程使用原生 HTTPLite。Android 使用现有异步 Java HTTPS 桥；需要带 INTERNET 权限和新版桥的网络 APK，原离线 APK 不会因本改动获得系统联网权限。
- Windows 更新已有检出时拒绝未提交修改或无法快进的分支，不再强制重置已有开发分支。无 Git 历史的初始安装仍从本仓库 `main` 初始化。
- 神秘礼物从本仓库 `main/Data/MysteryGift.txt` 获取。Debug 礼物管理的导出位置也改为 `Data/MysteryGift.txt`；制作、选择发布礼物并导出后提交此文件即可。当前仍是原有每存档按礼物 ID 记账的机制。
- 旧 `OnlineWondertrade` 仅保留兼容地图事件的提示，不选择或交换精灵、不访问 localhost。独立单机 `pbWonderTrade` 不变；在线交换使用现有联机池。

## 验证

`tests/resources/offline_resources_test.rb` 覆盖清单边界、路径与主机限制、截断和同长度篡改、原子替换、续传补齐、失败重试、取消、更新提示、无网络完整性检查、按需补图、本地图鉴保留与旧交换停用。`tests/resources/download_smoke.rb` 为显式联网探针，仅下载一张固定版本的小图集，验证实际 HTTPS、进度、校验和取消后清理。`tests/resources/game_smoke.rb` 在隔离的 Game.exe 中验证清单解析、校验窗口和实际开始菜单；测试不访问网络或玩家存档。

此改动发布源码和资源清单，不重建发行 ZIP/APK。完整资源包下载和 Android 实机网络界面仍需单独验收。
