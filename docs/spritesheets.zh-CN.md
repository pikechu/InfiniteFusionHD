# U09：图集与独立 PNG 共存

Issue：[#3](https://github.com/pikechu/kurayshinyrevamp/issues/3)。本次实现沿用 IF 6.4 的图集布局，接入 KIF 的现有立绘和配色链路；不批量转换用户图片或存档。

## 使用方式

选项中的 **Sprite sheets** 提供三档：`Off` 仅走原有 PNG 查找；`Local` 为默认，缺少独立自定义 PNG 时使用已安装图集；`Online` 可按需下载缺失图集，且必须同时开启 `Download data`、具有可用的平台 HTTP 能力。

已有独立自定义 PNG 优先。未覆盖旧的形态后缀、特殊命名、蛋、图标和三重融合资源；图集缺失、透明空格、HTTP/PNG/写入失败继续原有 PNG/占位图路径。切换到 Off 后，已保存且仍存在的缓存 PNG 仍可作为个体立绘显示。

从 IF 目录 `Graphics/` 下安装以下相对路径即可使用本地图集：

| 内容 | 目录 | 布局 |
| --- | --- | --- |
| 基础物种 | `CustomBattlers/spritesheets/spritesheets_base/H.png` | 96×96 单格，10 列；主立绘为第 0 格，a=1、z=26、aa=27 |
| 自定义融合 | `CustomBattlers/spritesheets/spritesheets_custom/H/Halt.png` | 96×96 单格，20 列；按 body ID 定位 |
| 自动生成融合 | `Battlers/spritesheets_autogen/H.png` | 96×96 单格，10 列；按 body ID 定位 |

在线源为 [infinitefusion/infinitefusion-e18 的 Graphics 目录](https://github.com/infinitefusion/infinitefusion-e18/tree/main/Graphics)。单张响应最多 16 MiB，宽度、行高和解码后纹理大小均验证后才安装。自动更新索引仍走原有素材更新流程，不为图集另设后台轮询。

## 缓存和存档

`SpriteSheets.rb` 管理下载、裁切及队伍预热。图集会裁成无配色的 PNG，再交给原来的 `AnimatedBitmap`、尺寸归一化、KIF/PIF 闪光与个体配色逻辑，避免共享已染色的 Bitmap。

- 自定义/基础缓存：`Graphics/CustomBattlers/spritesheets/kif-cache/`。
- 自动融合缓存：`Graphics/Battlers/spritesheets/kif-cache/`。
- 版本键包含素材包年月、源地址和基础/融合索引文件的 SHA-256。图集文件路径、长度、mtime、ctime 构成来源指纹；变更后使用不同的裁切路径。
- 裁切路径编码类别、head、body、alt 和版本。闪光磁盘缓存的前缀同时包含该来源路径，原有配色参数后缀继续生效，防止包更新后读到旧闪光图片。
- 存档可保留裁切路径或待解析标识；加载时根据逻辑素材重新解析当前版本，本地独立 PNG 仍优先。交换协议发送 `base:...` / `fusion:...` 标识，不发送本机缓存目录，接收方须有相同素材或本地图集。
- 解码图集最多保留两张；Windows 纹理总预算 64 MiB，Android 24 MiB，逐出时调用 Bitmap.dispose。图鉴候选列表只存路径，最多持有 8 个已归一化 Bitmap，页面关闭时释放。队伍预热仅处理前 6 只且不联网。
- 下载和裁切先写临时文件，再原子改名；同一会话每个缺失图集最多请求一次。选项切换/显式 clear 会释放内存。磁盘缓存归本功能所有，可在退出游戏后删除这两个 `kif-cache` 目录重新生成；程序不删除用户 PNG，旧版本磁盘目录不自动清理。
- 作者查询额外保留最多 256 条结果（含未找到），作者文件变化后失效；保留原来同名记录取第一条的规则。首次查询仍按需扫描 CSV，不在 Android 常驻整份作者表。

## 验证与指标

2026-10-22 在默认 Windows Game.exe（Ruby 3.1.3）及 Android 原生 mkxp（Ruby 3.4.10，API 30 x86_64 模拟器运行 ARM64 游戏、SwiftShader）执行。彩色/透明格为确定性 PNG 夹具，保证能判断行列、变体与配色是否串用。它们不是游戏美术的外观验收图。

Windows、Android 各自的 U09 52 项检查和 63 项真实 Pokemon 交换/存档回归通过；独立事务测试 88 项、客机状态与外观契约 154 项通过。涵盖三类图集、空格、异常数据、来源和版本失效、同物种不同个体、闪光、PNG 导出、正反融合预览、按需图鉴候选、真实大图标仓库切箱、图鉴页面开关与生命周期、作者缓存及其失效。

| 指标 | Windows 完整原生检查 | Android 完整原生检查 |
| --- | --- | --- |
| 源码加载到隔离游戏初始化完成 | 约 5 秒 | 约 52 秒 |
| 三类图集首次提取总时长 | 0.125 秒 | 0.861 秒 |
| 100 次已有裁切缓存查找 | 0.220 秒 | 0.421 秒 |
| 两个满仓库、大图标，连续切箱 4 次 | 3.269 秒 | 3.603 秒 |
| 打开图鉴变体页 / 翻页 20 次 | 0.423 / 0.233 秒 | 3.732 / 4.053 秒 |
| 图集纹理峰值 | 38,338,560 字节，低于 64 MiB | 20,275,200 字节，低于 24 MiB |
| 游戏进程内存 | 采样工作集峰值 831,574,016 字节 | 结束时 RSS 823,868 KiB |

Windows 指标对应 `u09-20261022-143100`，Android 对应 `android-sheets-3eccea102b`。完整探针分别耗时 13.83 秒和 111.66 秒。启动项为源码探针开始至隔离游戏对象就绪，不是从点击图标到标题菜单。包含真实 UI 绘制/动画和共用机器上的负载，不能据此推断所有机器的帧率提升。纹理预算只统计本功能持有的图集，不是整个游戏的内存限制；两端进程内存指标的采样时点和口径不同，不能直接比较高低。

作者缓存修复前，Android 同一场景 20 次翻页耗时 75.760 秒，修复后 4.053 秒；Windows 从 2.756 秒降为 0.233 秒。定位到每次翻页都在扫描约 4.4 MB 的 CSV，缓存避免重复读取相同名称。不同物种/新作者的首次查询仍可能产生开销。前一轮 Windows 冷提取曾因负载测得 2.151 秒，也说明单次计时不宜作为统一发布性能承诺。

独立 Android 后端探针另有 13 项通过：首次提取 3 张图集 1.075 秒、100 次缓存查找 0.315 秒、300 次解码并释放已裁切 PNG 1.009 秒、100 次枚举 0.165 秒、纹理峰值 20,275,200 字节。没有 HTTP 适配器时 0.001 秒安全返回离线。该组不计完整页面性能。

Android HTTPS 兼容探针使用已安装测试 APK 的 TLS 桥和**显式提供的当前平台适配器**，真实下载 IF 图集 1/1.png 用时 2.722 秒，原生解码、裁切和复用成功。外部适配器路径/哈希保存在该次证据中，不包含在本任务提交里；当前目标分支未提供此适配器时仍保持离线。未重打 APK，也不宣称完成实体设备、完整剧情或混合平台在线对战验收。

实际收益是支持 IF 图集分发、复用裁切 PNG、避免图鉴一次解码全部变体、限制图集纹理内存，以及消除已实测的重复作者扫描开销。没有证据表明冷启动或已有独立 PNG 的仓库必然变快，因此默认保持 Local，在线下载需要用户选择。

## 复现

Windows：`scripts/upstream/validate-task.ps1 -Task U09 -RefreshCatalog`。脚本创建专用存档目录，输出 `feature-smoke.log`、`native-metrics.json`、仓库/图鉴截图，最后由真实游戏导出 12 个租借候选、注册 48 个招式。构建摘要及可信目录随本任务提交。

Android：`python scripts/upstream/run-android-sheets.py --adb <adb路径> --full-game --timeout 240`。需要已安装可调试的 KIF 测试运行时；把本分支源码解压到独立诊断目录，使用新建测试玩家，不读玩家存档。脚本拒绝在已有游戏进程运行时启动，备份并还原诊断入口和配置，核对恢复后的 SHA-256。去掉 `--full-game` 只跑图集后端；可用 `--platform-source <路径>` 显式验证其他平台适配器，不能把这种结果当作目标分支已包含该依赖。

依据：[IF 图集加载源码](https://github.com/infinitefusion/infinitefusion-e18/tree/064a09664aca2e83e28dff436fa37fff72236481/Data/Scripts/048_Fusion/Sprites)。实现和长期可复现测试均随本分支提交；忽略目录 `temp/multiplayer/` 仅保存本机运行日志，不作为唯一交付依据。
