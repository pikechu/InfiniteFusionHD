**受控在线角色：独立 GOLD 与库存**

当前新角色使用[原版主线、战斗与培养](multiplayer-original-rules-completion.zh-CN.md)，并支持原版精灵市场、双方交易及双人复核的角色整档回滚。下文早期 v1 记录作为历史设计保留；旧服务器资产使用迁移入口，不再新增简化章节奖励。

2026-10-22 已确认的产品选择：新建受控在线角色；现有存档继续原玩法，历史资产不进入可信经济。

2026-10-23 已在资产模式之上交付[受控主线 v1](multiplayer-controlled-mainline.zh-CN.md)：14 个章节、服务端回合战斗、捕获、经验与努力值、回忆招式、进化、繁殖孵化、融合分离。客户端报告的胜利、掉落、旧存档余额或背包仍不能增加受控资产。

**入口与规则**

游戏在线模式暂停菜单新增「受控在线角色」。可创建和切换独立角色，查看 GOLD、领取签到、购买/出售受控库存；角色菜单中的「受控主线与培养」进入服务器章节模式。网络沿用现有异步传输及持久请求日志，不改动 `$Trainer.money`、本地主线背包或精灵。

| 范围 | 当前默认规则 |
| --- | --- |
| 角色 | 每个注册账号最多 3 个，服务器生成 `cc_` 编号；角色所有权绑定账号 |
| 初始 GOLD | 每账号一次 1,000，发到首次创建的角色；增加角色不重复获得 |
| 签到 | 每账号在 Asia/Shanghai 自然日一次 100，可选择领取到哪个角色 |
| 背包 | 由服务器保存，每种道具最多 999；伤药、精灵球及九种进化石 |
| NPC 买卖 | 服务器读取本项目可信物品目录价格、检查库存与余额；伤药和精灵球买入 200、卖出 100，进化石使用各自目录价格 |
| 货币隔离 | GOLD 属于受控角色；MARKET、RP 属于在线账号；旧存档金币另列快照 |
| 账号控制 | 封禁、维护、经济冻结同样作用于受控角色，查询与管理审计按原权限执行 |

数值是本项目首版配置，不代表 PokeMMO 的配置。`server/multiplayer/catalog-controlled-v1.json` 包含版本、配置和 `Data/items.dat` 来源哈希，可用可信本地游戏数据重新导出：

```powershell
& '<Ruby>' --disable-gems scripts/multiplayer/export-controlled-catalog.rb
```

目录版本固定为 `controlled-assets-v1`。购买确认提交目录哈希、单价、数量、角色版本和钱包版本；价格或状态变化时拒绝旧报价，不静默使用新价格成交。出售先核实服务器实际持有量，不从本地背包扣取或导入物品。

**数据与账本**

`controlled_characters`、`controlled_inventory` 保存角色与库存；`controlled_claims` 以账号和日期/初始发放范围去重；`controlled_item_events` 记录物品增减；`controlled_receipts` 长期保存请求回执。角色与钱包分别使用递增版本。

GOLD 复用现有 `shop_wallets`、`shop_ledger` 和双方分录，没有另一套独立的货币写入逻辑。钱包主键中的拥有者为受控角色编号。初始、签到和 NPC 收购道具是发行来源；NPC 出售道具消耗 GOLD 时记为销毁。所有变更、物品事件和回执在同一事务提交；任一条件失败则全部回滚。

后台首页显示 GOLD 总量、当日产出、当日回收和角色数。「经济与账本」按 GOLD、MARKET、RP 分开查看，提供可用/受限余额、来源去向、排行榜和对账。旧存档角色归并的 `char_` 编号只用于快照去重，不是受控角色，也不能给 `cc_` 钱包充值。

管理员在玩家详情可查看受控角色、钱包和背包。钱包调整检查账号所有权及钱包版本，适用原有额度复核。库存增减全部需要独立管理员复核，执行时重新核对账号控制版本、角色版本、当前数量与目录。发起人权限被撤销或申请过期后不可执行。库存日志追加写入，后台风险检测可发现数量与日志不一致。

**玩家接口**

接口使用现有账号 Bearer 凭据；普通玩家只能操作自己的角色，POST 沿用 `request_id`。

| 接口 | 作用 |
| --- | --- |
| `GET /v1/controlled/catalog` | 受控目录及报价哈希 |
| `GET /v1/controlled/characters` | 当前账号角色列表 |
| `GET /v1/controlled/characters/{id}` | 当前角色钱包、版本、库存 |
| `POST /v1/controlled/characters` | 名称与目录哈希，服务器分配身份和初始发放 |
| `POST /v1/controlled/characters/{id}/daily` | 账号当日签到，需角色版本 |
| `POST /v1/controlled/characters/{id}/buy`、`sell` | 道具、数量、目录哈希、报价和版本 |

没有导入存档、导入道具、导入精灵或由客户端声明奖励金额的接口。主线、捕获及培养统一使用 `GET/POST /v1/controlled/characters/{id}/adventure`，详见[规则与接口](multiplayer-controlled-mainline.zh-CN.md)。
